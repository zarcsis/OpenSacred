# Running and driving the original

The original is the developer's own `Sacred.exe` in `OriginalGame/` (a link to the GOG installation; in a worktree, link it first as for the ignored tests). `tools/original/host.py` starts it under Frida with `tools/original/agent.js` loaded, and serves the game's own remote-control methods on `127.0.0.1:15703` (docs/03 §3.8, #448). The maintainer allowed Claude Code to start it at any time (#448, decision 3): it runs in the background, never takes the focus, never blocks the maintainer's keys and never outlives its host.

## Start and stop

```bash
uv run python -I tools/original/host.py --holder <session> --log-file <scratch>/original.log   # run_in_background; one original at a time
uv run python -I tools/game/remote.py --port 15703 wait-state menu           # up, on its main menu
uv run python -I tools/game/remote.py --port 15703 exec "new-game --class seraphim"
uv run python -I tools/game/remote.py --port 15703 wait-ready                # in the world, the first windows closed
uv run python -I tools/game/remote.py --port 15703 exec "save start-seraphim"   # later: exec "load start-seraphim"
uv run python -I tools/game/remote.py --port 15703 click 720 480             # the hero walks there
uv run python -I tools/game/remote.py --port 15703 screenshot <scratch>/menu.png
uv run python -I tools/game/remote.py --port 15703 logs --after 0
uv run python -I tools/game/remote.py --port 15703 exec quit                 # the game closes as its window is closed
```

The host checks `Sacred.exe` against the manifest and refuses to start while a `Sacred.exe` runs or another host holds the original. Before each start it writes `FULLSCREEN : 0`, `SHOWMOVIE : 0` and the three volumes 0 into `Settings.cfg` (keeping the volumes it replaces in `%LOCALAPPDATA%\OpenSacred\original-volumes.json`, which `--sound` writes back), and the window's keys of dgVoodoo2's `dgVoodoo.conf` back to their defaults, and nothing else. It exits with the game's exit code: 0 after `quit`; 4 when its heartbeat stopped for 5 s; 5 when the agent was unloaded; 3 when the game asked DirectDraw for full screen; 6 when `--monitor` names no monitor.

Stopping the host's background task ends the game within a second (a job object). A run that hangs is ended by stopping that task, never by killing `Sacred.exe` by hand while the host lives.

One original runs on the machine, whichever worktree starts it. `--holder` takes this session's name as `ListAgents` shows it: while the host runs it records the holder, the Claude Code session, the branch and the worktree in `%LOCALAPPDATA%\OpenSacred\original-holder.json`, removed as the host ends, and a host started meanwhile refuses with them and how long they have held it (#1398); a record whose host is gone is taken over. When the host refuses, ask the holder it names (`ListAgents`, `SendMessage`) to say when the original is free (a session idle may still hold it), never ending another session's original (docs/03 §3.5).

| Option | What it does |

| `--arg WORD` | a word of `Sacred.exe`'s command line, as `--arg tabblocker` (docs/re/window.md) |

## What the client does here

| Call | What it does |
|---|---|
| `state` (`--json`) | the screen (`menu`, `loading`, `game`, `paused`: the game's time stands, under the menu over a game, the saves' list or a tutorial window), `ready` (a game, nothing scripted running); in a game the hero's cell, sector, floor, gait and whether it moves, its health, level and experience, the clock and its phase, the zoom, the creatures and objects counted, the nearest creature; the process, the frames drawn and the rate, the window's rectangle, whether the game believes it has the focus, the agent's cursor, the guards' refusals; the interface's line `ui`: the mouse's point and the point before, which the interface tests a click at, what the cursor holds, and in a game the controls under each point and the keyboard's focus (#1340) |
| `wait-state menu\|loading\|game\|paused`, `wait-ready` | poll until then |
| `key NAME` (`--hold N`) | press and release a key, held N frames (Alt over the labels), as opensacred-game names them: `Escape` (the menu over a game), `Enter`, `Space`, `L` (the log book), `F1`…`F12`, `NumpadAdd`, `Control+…`; a key with a character sends it too, as a keyboard does |
| `type "TEXT"` | characters, as into a name's field |
| `click X Y` (`--button left\|right\|middle`, `--hold`) | a click on a pixel of the window, 1024 × 768: a menu's item, an item of the inventory, the ground to walk there, an item on it to take it up; the move before it is posted twice, so that the mouse's point before is the click's too (#1340, docs/re/window.md, "The mouse's two points") |
| `move X Y`, `wheel N` | the cursor (moved twice, as `click`), the wheel |
| `screenshot FILE` | the next frame, as the original's own screenshot (`captureScreenshot`) converted to PNG |
| `logs --after N` | the host's records (`host`), the agent's (`agent`: each guard's refusal) and the game's own log (`game`) |
| `exec help` | the commands |
| `exec "new-game [--class C] [--difficulty bronze] [--name N] [--skip-tutorial\|--leave-open]"` | from the main menu, the Ancaria campaign with a class of `seraphim` (by default), `gladiator`, `mage`, `wood-elf`, `dark-elf`, `daemon`, `dwarf`, `vampiress`; OK and No more Tips close the first windows unless `--skip-tutorial`, or `--leave-open` leaves the first window to `ui press`; then `wait-ready` |
| `exec "save NAME"`, `exec "load NAME"`, `exec saves` | through the original's own menus: a save of that name is overwritten, else a new one is made in `save/`; a load from the main menu or a game; then `wait-ready`; not while a tutorial's or the first window is open, which takes the menu's clicks inside its rectangle |
| `exec ui`, `exec "ui press WINDOW CONTROL [--button left\|right]"` | the interface's windows shown, their controls' names, classes and rectangles, the manager's field of each window, and a tooltip's links (the first window's and the tutorial's OK and Skip Tutorial) named by the scripts' functions they run; a click in the middle of the control or link of that name within that window, as a player clicks it (#1340, docs/re/window.md, "The interface's controls"), as `ui press UI_WND_TASKBAR UI_TB_INVENTORY` or `ui press UI_WND_TOOLTIP btn_Deamonstart` |
| `exec "creatures [RADIUS]"` | the creatures within RADIUS cells of the hero (20), not the destroyed ones whose slots wait to be taken again (#1105), the nearest first: id, type, cell (and floor inside), health, level, `hostile` or `peaceful` to the hero, `champion` or `boss`, the AI's and the action's states (docs/re/ai.md), the target's id, its dialogue's index (`+0x245`) where it has one, its side (`+0x1F0`), its flags word (`+0x1F4`) and its master's id (`+0x251`) where it follows one, and `enter` where a sector's `Enter` made it, which its sector's exit destroys, or `enter fill` where a fill did, which the exit keeps while it lives (docs/re/spawning.md, #1103) |
| `exec "stats [ID]"` | a creature's stats, the hero's by default (`+0x3A8`): its attributes and base ones, `A` and `D` with their multipliers, each kind's least and most damage with the items' and the attributes' multipliers, the resistances with theirs, the attack speed and the health; the raw values, which the attack record multiplies (docs/re/fight.md), each float exactly (the shortest decimal that reads back as it) |
| `exec fpu` | the x87 control word and its precision (24, 53 or 64 bits) on the render thread's frame, where the commands run, and in the latest stats' recomputation (`0x5796A0`) and strike (`0x56B130`), with their threads (#589) |
| `exec "cell X,Y [FLOOR]"`, `exec "sector X,Y"` | the hero onto the cell, or the nearest it may stand on, as the scripts' `Teleport` puts a player; floor 0 is the ground even within a building's walls, 1 a building's ground floor |
| `exec "cell-info [X,Y\|+DX,+DY]"` | what a cell is, the hero's by default, through the original's own functions (#568, docs/re/movement.md, "Positions and layers"): its sector, its building and floors; for the ground, each floor of the building and the hero's own layer, the cell's nature, ground byte and flags, what its low nibble makes it (a mass, a wall or water, an entrance, an exit, a stair and its offsets, a teleport), a door's trigger and state, whether it may be walked on, whether the hero may stand there (as `cell` places it), its corner heights (drawn and standing, the cell's raw bytes) and the height it stands at (units of the models' height); the objects of each level's cell, the hero among them; a sector not in memory is refused |
| `exec "go X,Y"`, `exec "go +DX,+DY"`, `exec "point X,Y"`, `exec "point #ID"` | a walk by a click on the cell's pixel (on the screen only), or the pixel alone for `click` (a creature's cell: an attack); the pixel at the height of the cell on the hero's level, the ground's or its floor's, so that a click inside a building picks a cell of the hero's floor (#979); `#ID` an object's own pixel, an item's on the ground, whose click takes it up (#1340) |
| `exec "god [on\|off]"` | the hero takes no damage (toggles without a switch): a strike at it leaves its health as it was, any other loss comes back at the next frame, and the original's own `lord` flag spares it the knock-downs (docs/re/objects.md, "The console's cheats") |
| `exec "heal [ID] [--to N]"` | a creature's health to its most, or to N (at most its most), the hero's by default |
| `exec "effect EFFECT VALUE [--whole N] [--seconds S] [--art A] [--id ID]"` | an effect on a creature's stats, the hero's by default, through the original's own `0x582D50`, for S seconds (60), then its `stats` (docs/re/arts.md, "The effects", #651) |
| `exec "arts [ID]"`, `exec "arts learn ART [LEVELS]"`, `exec "arts ready"`, `exec "arts use ART"`, `exec "arts select ART"` | a creature's combat arts (the hero's by default): each entry's table (`spell` or `art`), id, level and bonus, the bit "learnt", the shortcut's slot, the time, the factor and the regeneration still to run; the hero learns an art or rises in it as that many runes teach it (below 1000 a spell); every art of the hero ready at once; an art's regeneration started as a use of it starts it, through the original's `0x562470`, its time added to every art of its kind (docs/re/arts.md, #623); an art put on the right button, the engine's `+0x5A` with `+0x58` 0 for a spell and 1 for a weapon art, for `click X Y --button right` on a target (#672) |
| `exec "weather rain\|fog\|snow\|quake N"`, `exec "weather clear"` | the weather's level asked, 0 to 100, as the original's console's `setrain`, `setfog`, `setsnow` and `setquake` ask it (the rain and the snow ramp by about 30 drops or 60 flakes a second, the fog by 3 of its alpha); `clear` fades every level to 0 (docs/re/weather.md, #1073) |
| `exec "pause [on\|off]"` | the world's time stands without the menu over a game (the timer's first byte, the screen `paused`), the frames and screenshots going on; toggles without a switch |
| `exec "level N"`, `exec "experience N"`, `exec "experience +N"` | the hero's level, by adding the experience the level starts at as kills add it (each level-up as play gives it), or its experience set or raised, its level following; the original's levels and experience only rise, so a lower one needs a new game |
| `exec "spawn TYPE [--at X,Y\|+DX,+DY] [--count N] [--level L] [--rank champion\|boss] [--hostile\|--peaceful] [--immortal]"` | creatures made by `FillSector`'s maker on the cell (the hero's by default) and the rings about it: at `L` exactly (1 to 250), else by `CreateNPC`'s rule held at the sector's highest, a rank at the marker level 1 (levelled at its first fight); hostile or peaceful by the type unless told; an immortal one takes each strike's damage, which the log tells (`agent: immortal …`), and gets its health back at once (docs/re/objects.md, "Making creatures, kills and drops") |
| `exec "kill [RADIUS]"` | the hostile creatures within RADIUS cells (5) die as the hero's kills, their drops and the hero's experience the game's own: the hero's unarmed strike sent at each at a health of 1, again while it misses (`by N strikes`; within about 27 cells, a strike's reach) |
| `exec "drop [TIMES] [--id ID]"`, `exec "item TYPE"` | the nearest hostile creature (or ID) drops as its death makes it drop, the hero its killer, TIMES times, each object made listed; an item of a type, as the hero's drop forced to it, at the hero's place and level |
| `exec "gold [N]"`, `exec "home [X,Y [FLOOR]]"` | the hero's gold (`state` shows it too), or set to N; the hero's home, where it rises after its death, or set to a cell on the ground or a floor (#973) |
| `exec "wear [TYPE] [--slot S]"` | what the hero holds and wears, by its 19 slots; with a type, an item of it made and put into its slot (or S), what the slot held put aside, then the hero's stats (#973) |
| `exec "script NAME"` | a function of the hero's script tree run by its name, found case aside, as the calendar's timers run theirs (`0x46BF40` with no object, #1100): its records act at once, as `opensacred-game`'s console's `script` runs one; whether it ran to its end |
| `exec "time HH:MM"`, `exec "day-speed DAY [NIGHT]"`, `exec "zoom Z"` | the clock, its rates (0 stops it), the zoom (0.5 to 2; the game settles on 0.5, 1 or 2) |
| `exec "trace PRESET\|GROUP\|ADDRESS …"`, `exec "untrace NAME\|GROUP\|all"`, `exec traces` | log every call of a function: the presets of docs/re/traces.md (`strike`, `chance`, `death`, `experience`, `drop`, `item`, `regen`, `wake`, `look`, `idle`, `door-search`, `door`, `trigger-set`, `trigger-reset`, `sound-pick`, `sound-event`, the samples and streams), the groups `fight`, `drops`, `ai`, `doors`, `sound`, or an address (or `MODULE!EXPORT`) with `--abi`, `--args` (kinds `int uint hex u16 i16 float ptr object id cstr out-float`), `--ret`, `--ids`, `--limit`; an address with `--stack KIND@REGISTER\|OFFSET\|REGISTER+OFFSET,…` probes that instruction, inside a function too, logging registers, `ESP`'s slots and the memory at a register plus an offset (`double` too) as it is reached (docs/re/traces.md); `call original/trace '{"target": …}'` does the same |
| `wait-log PATTERN [--after N] [--timeout S]` | wait for a record whose `target: message` matches, as `wait-log "trace: drop: .*gold"` |
| `exec quit` | the game closes as its window is closed, and the host with it |
| `tools/game/compare.py X,Y …` | with the game (`--remote`) running beside it, both heroes onto each cell and their creatures compared: the pairs of a type whose level, most health, hostility or rank differ, and the creatures of one game alone (docs/03 §3.7, #574) |
| `tools/game/compare.py stats --types T,… --levels L,…` | each type made at each level in both games and their fight values compared, the original's taken through its multipliers as its attack record does (#587, #589) |
| `tools/game/conformance.py [--suites experience,hero,stats,drops,places,regeneration,strikes,arts,movement]` | a conformance run with both games: PASS or FAIL per check, a non-zero exit on a failure; it reloads both (`--save`, the Seraphim's new game) before each suite (docs/03 §3.7, #600) |
| `shell` | the maintainer's, by hand in a terminal (#550): a line a command of the original (`cell 3296,2528`, `creatures 20`), `:CALL` one of these (`:state`, `:click X Y`, `:screenshot FILE`, `:logs`, `:follow on`, `:help`), `:quit` leaves the game running |

The input goes to the game as the agent's own messages: the keys and cursor the game queries are the agent's, and the maintainer's keyboard and mouse never reach it, nor does input posted to the window from outside. A level-1 hero teleported among monsters dies within seconds (it rises again at its start): `god on` first, or place it at a distance and read `creatures` first.
The traces see what the commands make the game do (a `kill`'s drops and experience among them), as the agent runs them from its replacement of the frame's function, outside its hooks. After one click the hero strikes once: click again for each strike, about every 1.3 s. A right-click on a creature makes the hero use its selected combat art on it (the Seraphim's 1071 at the start: `arts ready` first, then `click X Y --button right` about 45 pixels above the creature's cell). A click at a creature's feet (`point` of its cell) hits the ground; click about 45 pixels higher, on its body.

## Rules

- Frames, logs and traces of the original stay in the scratchpad: never in the repository (docs/08 §3). Write what they show in words, the results into #227 and `docs/re/`. A frame of the original beside the game's, cropped to a problem that shows on the screen, goes to its issue or pull request as an attachment (`gh … --attach`; CLAUDE.md, "Issues and pull requests"); logs and traces never.
- The game may overwrite the files it writes itself (`Settings.cfg`, `save/`, `Capture/`, its logs); never touch a file of the manifest, and add nothing to `OriginalGame/` beyond dgVoodoo2's two DLLs and its `dgVoodoo.conf` (docs/03 §3.8).
- The agent hooks the running process alone and carries only addresses, offsets and the original's names (docs/re/window.md): no decompiler output, no code translated from it.
